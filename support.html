Configuration guides, troubleshooting, and security recovery playbook

What is Deckhand?

Deckhand is a high-performance SSH terminal and coding agent supervisor designed for iPhone and iPad. It allows developers and system administrators to connect securely to remote Linux, macOS, or BSD servers, attach to persistent tmux sessions, and supervise autonomous coding agents via Herdr.

System Requirements

  • iOS & iPadOS: Version 26.0 or later recommended (compatible with modern iPhone and iPad hardware).
  • Remote Host: Any standard OpenSSH server (sshd) supporting password, Ed25519, or ECDSA authentication.
  • Agent Supervision (Optional): Remote server running herdr version 0.9.1 or higher.
  • Mesh Networking (Optional): Tailscale iOS application installed on device if connecting via Tailscale 100.x.y.z addresses.

Frequently Asked Questions

1. How do I add my Deckhand public key to my server?

To authenticate using a public key generated in Deckhand:

  1. Open Deckhand and tap Keys in the navigation bar.
  2. Tap your key (e.g. Secure Enclave P-256 or Ed25519).
  3. Tap Copy Public Key (or display the QR code).
  4. On your remote server, append this key to your user's ~/.ssh/authorized_keys file:
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo "PASTE_PUBLIC_KEY_HERE" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys

2. Why does my connection fail or say Tailscale looks unreachable?

If you are connecting to a server via a Tailscale MagicDNS hostname or 100.x.y.z IP address:

  • Verify that the Tailscale VPN is active and connected in your iOS Settings or Tailscale app.
  • Ensure that your target device is online in your Tailscale admin console.
  • Pro Tip: Configure Fallback Endpoints in Deckhand's Host Editor. You can provide both your server's Tailscale IP and its local Wi-Fi LAN IP (e.g., 192.168.1.50). Deckhand will automatically attempt fallback addresses without hanging.

3. Host Key Verification Failed / Host Key Changed Warning

Security Warning: Deckhand strictly enforces Host Key Pinning on first use. If a server presents a host key fingerprint different from what you previously trusted, Deckhand will block the connection immediately to protect you from Man-in-the-Middle (MitM) attacks.

If you recently reinstalled your server OS or deliberately regenerated your server's SSH host keys:

  1. Open Deckhand Settings › Known Hosts.
  2. Find the server entry and swipe left to delete the pinned fingerprint.
  3. Reconnect to the server. You will be prompted to inspect and trust the new host key fingerprint.

4. Face ID was re-enrolled and my key stopped working

For maximum security, keys generated in the Secure Enclave are bound to the user's biometric state. If you reset Face ID, add an alternate appearance, or reset device biometrics:

  • iOS marks the existing biometric access control token as invalidated.
  • This is an intentional operating system security measure to prevent unauthorized access if someone adds their face to your phone.
  • To resolve: generate a new key in Deckhand, export its public key, and add it to your server's authorized_keys.

5. How does the Herdr Agents inbox work?

Deckhand integrates natively with Herdr over your authenticated SSH connection:

  • When you open the Agents tab, Deckhand queries the remote Herdr daemon socket.
  • If an agent enters a blocked state (such as requiring permission to run a command or requesting clarification), Deckhand flags it with the ⚑ Needs you signal badge.
  • You can tap the agent card to review the context and submit quick answers or keystrokes (such as 1, Enter, or Esc) directly from your phone.

Lost or Stolen Device Playbook

Incident Response Guide: If your iPhone or iPad running Deckhand is lost, stolen, or compromised, execute these steps immediately to safeguard your server infrastructure.
  1. Revoke the Public Key on Your Servers:

    SSH into your servers from a trusted computer and remove the device's public key from ~/.ssh/authorized_keys:

    # Open authorized_keys and delete the line containing the device key:
nano ~/.ssh/authorized_keys
  2. Revoke Tailscale Node Access:

    If the device was connected to your private Tailscale tailnet, log in to the Tailscale Admin Console, locate the missing device, and click Remove Machine or expire its authorization key immediately.

  3. Terminate Active Sessions:

    Terminate any active SSH or tmux sessions that may have been left open from the device:

    # Kill active sessions for your user:
pkill -u $USER -t pts/0
  4. Initiate Apple Remote Device Wipe:

    Log into iCloud Find My from any web browser and initiate Erase Device. This immediately destroys the local Secure Enclave keys and clears the encrypted application sandbox.

Hardware Protection Note: Because Deckhand uses Apple's hardware Secure Enclave with biometric gating, an attacker cannot extract your raw private keys even with physical possession of the hardware.
